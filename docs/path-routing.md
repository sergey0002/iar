# Маршруты в пути: псевдонимы, пресеты и макросы

`aliases.json` — один JSON-файл рядом с `index.php`, который превращает короткий
URL в реальный путь к файлу и в набор параметров обработки.

```
/iar/z/file.png          →  /z/s/d/f/file.png
/iar/1000/file.png       →  /file.png?w=1000
/iar/x-2000/file.png     →  /file.png?w=2000     (только ширина)
/iar/y-1000/file.png     →  /file.png?h=1000     (только высота)
/iar/z/thumb/file.png    →  /z/s/d/f/file.png?w=300&h=300&m=cover
```

Файл уже лежит в репозитории и работает сразу: скопировали папку IAR на сайт —
маршруты включены. Ничего доустанавливать и нигде регистрировать не нужно.

---

## 1. Быстрый старт

1. Откройте `aliases.json` в папке IAR (там же, где `index.php`).
2. Опишите свои каталоги и пресеты.
3. Готово. Никаких команд, кеша конфигов и перезапусков.

```json
{
    "aliases": {
        "z": "/z/s/d/f/",
        "img": "/assets/images/"
    },
    "presets": {
        "1000": {"w": 1000},
        "thumb": {"w": 300, "h": 300, "m": "cover", "g": "center"},
        "avatar": {"w": 128, "h": 128, "m": "cover", "g": "top", "fm": "webp"}
    },
    "macros": {"enabled": true, "width": "x-", "height": "y-"}
}
```

Ключи с подчёркивания (`_readme`, `_aliases`, `_presets`, `_macros`) — это
комментарии: они игнорируются и в верхнем уровне, и в именах псевдонимов
и пресетов.

Хотите выключить маршруты, не удаляя файл? Поставьте `"enabled": false`.
Хотите выключить только маски — `"macros": {"enabled": false}`.

---

## 2. Три механизма

### 2.1. Псевдоним каталога (`aliases`)

Ключ — короткий префикс URL, значение — реальный каталог **относительно
`images_base_dir`** (корня оригиналов, по умолчанию — корень сайта).

| Запрос | Реальный файл |
| --- | --- |
| `/iar/z/file.png` | `<корень>/z/s/d/f/file.png` |
| `/iar/img/2026/hero.jpg` | `<корень>/assets/images/2026/hero.jpg` |

Правила:

* крайние слэши не важны: `"/z/s/d/f/"`, `"z/s/d/f"`, `"\z\s\d\f\"` — одно и то же;
* побеждает **самый длинный** префикс: при `a` и `a/b` путь `a/b/c.png` уйдёт в `a/b`;
* хвост пути сохраняется целиком: `img/2026/hero.jpg` → `assets/images/2026/hero.jpg`;
* `"root": "/"` — псевдоним на сам корень оригиналов;
* псевдоним работает и в глубине: `z/2026/file.png` → `z/s/d/f/2026/file.png`.

### 2.2. Пресет — последняя папка как набор GET-параметров (`presets`)

Имя папки **непосредственно перед именем файла** — это имя пресета. Папка
виртуальная: она вырезается из пути, а её параметры подставляются в запрос.

```
/iar/1000/photo.jpg   →  photo.jpg?w=1000
/iar/thumb/photo.jpg  →  photo.jpg?w=300&h=300&m=cover
/iar/avatar/user.jpg  →  user.jpg?w=128&h=128&m=cover&g=top&fm=webp
```

Пресет — это ровно те же параметры, что и в URL, поэтому кеш-ключ совпадает:
`/iar/thumb/photo.jpg` и `/iar/photo.jpg?w=300&h=300&m=cover` — **один файл в кеше**.

Разрешённые ключи пресета (белый список URL API):

| Ключ | Смысл |
| --- | --- |
| `w`, `h` | максимальная ширина / высота в пикселях |
| `m` | режим: `fit`, `cover`, `resize` |
| `g` | точка кадрирования: `center`, `top`, `bottom`, `left`, `right`, … |
| `fm` | формат: `jpg`, `png`, `webp`, `avif`, `gif` |
| `ct`, `cr`, `cb`, `cl` | обрезка края: `50` (пиксели) или `15p` (проценты) |

Всё остальное (`name`, `quality`, произвольные ключи) молча игнорируется:
пресет не может ни переназначить файл, ни залезть в настройки движка.
Значения проходят **ту же валидацию**, что и параметры запроса: `"w": -5`
даст обычный `400`, а не тихую подмену.

### 2.3. Макрос — маска последней папки (`macros`)

```
/iar/x-2000/file.png  →  file.png?w=2000
/iar/y-1000/file.png  →  file.png?h=1000
```

* `x-<число>` — **только** максимальная ширина;
* `y-<число>` — **только** максимальная высота;
* один макрос = ровно один параметр. Комбинаций вида `x-1000-y-500` нет:
  два ограничения задаются пресетом или обычным query;
* число — 1…6 цифр, значение ≥ 1 (`x-0`, `x-`, `x-12a`, `x-1234567` — не макрос);
* префиксы настраиваются: `{"width": "w", "height": "h_"}` → `/iar/w800/a.png`.

---

## 3. Приоритеты (важно)

1. **Реальный файл важнее виртуального маршрута.** Если по буквальному пути
   файл на диске есть, маршрут не применяется. Каталог `thumb/`, который уже
   существует, продолжит работать как раньше — старые ссылки не ломаются.
2. **Query важнее пути.** `/iar/thumb/photo.jpg?w=50` даст ширину 50, остальные
   параметры пресета сохранятся. Пустое значение (`?w=`) считается отсутствующим,
   а `?w=0` — осознанным «без ограничения по ширине».
3. **Пресет важнее макроса.** Если имя папки есть и в `presets`, и подходит под
   маску, применяется пресет.
4. **Только последняя папка.** `/iar/1000/nested/photo.jpg` — обычная папка
   `1000`, никакого пресета. Виртуальной может быть лишь папка перед файлом.
5. **Псевдоним применяется после пресета.** `z/thumb/file.png` → сначала
   вырезается `thumb`, затем раскрывается `z`.

---

## 4. Надёжность и безопасность

* **Сломанный JSON не ломает картинки.** Невалидный файл → маршрутизация
  выключается, изображения отдаются как обычно, причина пишется в лог
  событием `fail` со `"stage":"aliases"`. Отсутствие файла — не ошибка.
* **Никаких выходов за корень.** В именах и целях псевдонимов запрещены `..`,
  `.`, NUL-байт, схемы (`http://`, `file://`) и буквы дисков (`C:`). Такие записи
  отбрасываются при загрузке. Дальше путь проверяет штатный разбор запроса
  (`realpath` + белый список расширений), как и без маршрутов.
* **Псевдоним не раскрывает реальный путь при сбое.** Обычный сбой обработки —
  это `302` на оригинал. Но если путь скрыт псевдонимом, редиректить некуда:
  оригинал отдаётся **прямо в теле ответа** (`200`, `X-Iar-Fallback: original`,
  `Cache-Control: no-store`). Реальный каталог не утекает ни в `Location`,
  ни в теле ошибки.
* **Аварийный путь тоже понимает маршруты.** Если конфиг сломан или произошла
  фатальная ошибка, IAR всё равно раскрывает псевдоним и отдаёт оригинал.
  Путь к `aliases.json` берётся из сырого конфига, а если и он нечитаем —
  используется файл рядом с `index.php`.
* **`aliases.json` закрыт от HTTP.** В `.htaccess` он добавлен в список
  служебных файлов: скачать карту реальных каталогов нельзя. Для nginx:

  ```nginx
  location = /iar/aliases.json { deny all; }
  ```

* Клиентские ошибки остаются клиентскими: `404` для отсутствующего файла,
  `403` для запрещённого расширения, `400` для неверного параметра. Маршруты
  не обходят белый список расширений и не отдают оригинал вместо `4xx`.

## 5. Кеш и производительность

Кеш-ключ строится из **итогового** пути и **итоговых** параметров, поэтому:

* пресет и эквивалентный query дают один и тот же файл кеша;
* два движка (Intervention и зависимости-не-нужны `legacy.php`) делят кеш
  и для маршрутов тоже — проверено тестом на паритет ключей;
* инвалидация по `mtime` оригинала работает как раньше: обновили файл —
  изменилось имя варианта, старые ссылки получают новый файл.

Стоимость маршрутизации на **cache hit** (замер `tools/io-probe.php`,
один запрос, современный движок):

| Ситуация | Обращений к ФС | Что добавилось |
| --- | --- | --- |
| `aliases.json` нет | 11 | `is_file` по файлу маршрутов |
| файл есть, путь обычный | 12 | + чтение небольшого JSON |
| путь маршрутизирован | 13 | + `is_file` проверки «реальный файл важнее» |

Для `legacy.php` те же три случая дают 13 / 14 / 15 операций. **Содержимое
оригинала на cache hit не читается ни в одном случае** — только `realpath`,
`is_file`, `filemtime`, как и раньше. Файл в корне сайта (`photo.jpg`) вообще
не разбирается: без слэша в пути маршрутов быть не может.

Точечная очистка кеша понимает те же маршруты: путь можно писать как в URL.

```bash
php tools/cache.php clean --source=z/thumb/photo.jpg --dry-run
# Очистка (оригинал z/thumb/photo.jpg (путь photo.jpg)): 2 файл(ов) …
```

## 6. Диагностика

При `logging => true` в каждом событии появляются поля маршрута:

```json
{"event":"miss","status":200,"alias":"z","preset":"x-2000","params":{"w":"2000"}}
```

* `alias` — применённый псевдоним (или `null`);
* `preset` — имя пресета или маски (или `null`);
* `params` — итоговые параметры (только на уровне `log_level => debug`).

Заголовки ответа не меняются: `X-Iar-Engine`, `X-Iar-Cache`, `X-Iar-Fallback`.

## 7. Ограничения (честно)

* Псевдоним — только префикс каталога. Регулярных выражений, шаблонов и
  подстановок в цели нет.
* Пресет не может менять имя файла, каталог или настройки движка — только
  параметры URL API из белого списка.
* Макрос задаёт одно измерение. Нужны оба — пресет или query.
* Виртуальной может быть только последняя папка. Вложенные пресеты
  (`/thumb/avatar/file.png`) не поддерживаются намеренно: путь должен
  оставаться читаемым.
* Маршруты применяются к пути из URI (и к `?name=` при прямом вызове
  `index.php`). Отдельного файла правил для nginx не требуется: существующее
  правило «изображения → index.php» уже пропускает виртуальные папки.
* Порядок ключей в JSON не важен, кроме псевдонимов: там приоритет определяется
  длиной префикса, а не порядком в файле.

## 8. Проверка

```bash
# Модульные тесты маршрутизатора и приоритетов
php tests/run.php                     # весь набор
IAR_TEST_FILTER=PathRouterTest php tests/run.php

# Совместимость и маршруты на PHP 7.0 … 8.4
php tests/legacy-compat.php

# Сквозные HTTP-сценарии (псевдонимы, пресеты, макросы, сломанный JSON)
php tools/integration.php run

# Покрытие строк с порогом 100 %
php tools/coverage-portable.php build && php tools/coverage-portable.php report 100
```

Что проверяется автоматически: паритет разбора путей между двумя движками,
приоритет реального файла, приоритет query, «только последняя папка», один
параметр у макроса, отбрасывание опасных определений, поведение при сломанном
JSON, отдача оригинала за псевдонимом, общий кеш пресета и query, работа
маршрутов на движке без зависимостей.
