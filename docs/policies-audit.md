## 1. Принцип именования кеш-файлов

**Формулировка пользователя:** имя должно быть «умным», чтобы по нему можно было чистить кеш точечно и понимать, чему файл соответствует.

**Реализация:** `src/Infrastructure/CacheKey.php`, зеркало — `iar_legacy_key()` в `legacy.php`.

```
{имяОригинала}__{W}x{H}{кроп}{режим}__{md5(относительногоПути)}_{mtime}{отпечатокНастроек}.{ext}

photo__300x0_ct10p_m-cover-g-top__72acded3acd45e4c8b6ed680854b8ab1_1795879327_4accfe70.jpg
└─ имя ─┘└─ размеры ─┘└─ кроп/режим ─┘└──── md5 пути оригинала ────┘└─ mtime ─┘└ настройки ┘
```

Что входит в имя и почему:

| Часть | Источник | Зачем |
| :--- | :--- | :--- |
| имя оригинала | `pathinfo(..., PATHINFO_FILENAME)` | человекочитаемость, поиск по префиксу |
| `WxH` + кроп + режим | параметры запроса | различение вариантов |
| `md5` **относительного пути** | `CacheKey::relativePath()` | различение одноимённых файлов из разных папок; **не хеш содержимого** |
| `mtime` | `filemtime` оригинала | версия оригинала |
| отпечаток настроек (8 символов) | `Config::qualityFingerprint()` | смена качества сразу даёт новый вариант |
| расширение | целевой формат (`jpeg` → `jpg`) | MIME определяется расширением |

**Чего в имени нет и почему:**

- **веса файла в байтах** — он ничего не идентифицирует и потребовал бы лишнего `filesize` на каждом запросе;
- **хеша содержимого** — это чтение всего оригинала, что прямо запрещено политикой производительности;
- **абсолютного пути** — он ломал бы перенос папки между серверами; используется относительный путь от `images_base_dir`.

**Проверено:** `CacheKeyTest` (11 тестов, включая коллизию одноимённых файлов в разных каталогах и имена с `[ ]`, `&`, пробелами и кириллицей), интеграция №40.
Кросс-движковая идентичность имени доказана тестами `LegacyTest::testCacheKeyMatchesMainEngine`, `testCacheKeyMatchesForEveryMode`, `testQualityFingerprintMatchesMainEngine`, `testHashMarkerMatchesMainEngine`, `testEnginesShareTheSameCacheFile` — вариант, созданный одним движком, второй читает как свой (`X-Iar-Cache: hit`).

**Вердикт: выполняется.**

## 2. Инвалидация: оригинал изменился

**Реализация:** `Application::resolveMtime()` → ключ содержит `mtime` → новое имя файла → старый вариант не может быть выдан.

Тонкость, исправленная в этом проходе: **очистка не должна вытеснять другие размеры актуальной версии**.
Раньше `CacheStore::cleanOldVersions()` удалял все варианты оригинала, кроме текущего, — страница с `srcset`
(три размера одного фото) перегенерировала кеш на каждый запрос. Теперь метод принимает четвёртый аргумент
`$currentVersion = "{mtime}{отпечаток}."` и удаляет только варианты **прошлых версий**, сохраняя все размеры текущей.

**Проверено:**

- `ApplicationTest::testDifferentSizesOfCurrentVersionCoexist` — после `w=100`, `w=200`, снова `w=100` ответ `hit`, в кеше 2 файла;
- `ApplicationTest::testOriginalChangeRemovesStaleSizes` — после `touch` оригинала остаётся 1 файл нужного размера;
- `CacheStoreTest::testCleanOldVersionsKeepsCurrentSizes` — 3 актуальных размера живут, 3 устаревших удалены;
- `LegacyTest::testCurrentSizesCoexist`, `testSelectiveCleanupOfOldVersions`;
- интеграция №33 (`mtime change invalidates and cleans old variant`), №41 (смена качества), №42 (`cache_invalidation=off`).

**Вердикт: выполняется.**

## 3. Инвалидация: оригинал удалён

**Поведение:** запрос к удалённому оригиналу → `404 File not found.` (оба движка). Вариант из кеша **не** выдаётся:
ресурса больше нет, отдавать его — значит показывать пользователю то, чего на сайте уже не существует.
Осиротевшие файлы кеша убираются точечно: `php tools/cache.php clean --orphans`.

Это осознанное решение: политика «картинка не должна пропасть» относится к **сбоям обработки**, а не к
удалению ресурса владельцем сайта. Разница зафиксирована в тестах, чтобы её нельзя было случайно поменять.

**Проверено:** `LegacyTest::testDeletedOriginalIsReportedAsNotFound`, интеграция №23, замер `clean --orphans` (удалён ровно 1 файл из 3, остальные целы).

**Вердикт: выполняется** (с явно задокументированной семантикой).

## 4. Точечная очистка кеша

**Формулировка пользователя:** не удалять всю папку; чистить адресно и с минимальными ресурсами.

**Реализация:** `tools/cache.php` — PHP 7.0+, без Composer, без чтения содержимого файлов.

| Команда | Что делает | Как находит файлы |
| :--- | :--- | :--- |
| `stats` | файлы, вес, число уникальных оригиналов, разбивка по форматам | `scandir` + разбор имени |
| `clean --source=photo.jpg` | все варианты одного оригинала | префикс `photo__` + маркер `__md5(путь)_` |
| `clean --orphans` | варианты удалённых оригиналов | множество «живых» маркеров обходом оригиналов |
| `clean --older-than=30d` | давно не создававшиеся варианты | `filemtime` кеш-файла |
| `clean --max-size=500M` | самые старые, пока вес больше лимита | сортировка по `mtime` |
| `wipe` | всё содержимое | — |

Все команды принимают `--dry-run`. Автоматическая очистка при генерации (`cache_auto_clean`) работает по тем же
маркерам и удаляет только прошлые версии одного оригинала — чужие файлы не затрагиваются.

**Замер (одинаковый результат на PHP 8.3 и PHP 7.0):** кеш из 6 вариантов четырёх оригиналов, один оригинал удалён,
один вариант «состарен» на 60 дней.

```
$ cache.php stats                        → Файлов: 6, вес: 3.54 KB, уникальных оригиналов: 4
$ cache.php clean --source=photo.jpg --dry-run → 3 файл(ов), 1.79 KB (ничего не удалено)
$ cache.php clean --source=photo.jpg     → 3 файл(ов), 1.79 KB
$ cache.php stats                        → Файлов: 3 (чужие варианты целы)
$ cache.php clean --orphans              → 1 файл(ов), 586 B
$ cache.php clean --older-than=30d       → 1 файл(ов), 595 B
$ cache.php clean --max-size=1           → 1 файл(ов), 608 B
```

**Вердикт: выполняется.**

## 5. Cache hit: никаких полных обработок и хешей

**Формулировка пользователя:** при наличии варианта недопустимо полностью обрабатывать исходник или считать `md5` его содержимого; максимум — размер/`stat`.

**Реализация и измерение.** Инструмент `tools/io-probe.php` подменяет файловые функции в копии дерева
(`.probe/`) и считает каждое обращение. Запрос: `photo.jpg?w=300`, оригинал 1200×800.

Ниже — базовый случай **без файла маршрутов** (`aliases.json` отсутствует): с него начиналась политика.
Стоимость маршрутизации измерена отдельно, в конце раздела.

**Основной движок, отдача через PHP (`redirect_to_cache=false`), cache HIT — 10 обращений:**

| Операция | Раз | Что именно |
| :--- | :---: | :--- |
| `is_file` | 4 | автозагрузчик, `config.local.php`, оригинал, вариант кеша |
| `realpath` | 2 | корень оригиналов, оригинал |
| `is_dir` | 1 | корень оригиналов (валидация конфига) |
| `filemtime` | 1 | **оригинал — единственная проверка версии** |
| `filesize` | 1 | вариант кеша, для `Content-Length` |
| `readfile` | 1 | вариант кеша |

**Основной движок, редирект на статику (боевой дефолт), cache HIT — 10 обращений, `readfile` нет вовсе**
(файл отдаёт Apache/nginx). К оригиналу — ровно три обращения: `realpath`, `is_file`, `filemtime`.

**Движок без зависимостей (`legacy.php`), cache HIT — 12 обращений** (на два больше: проверка `vendor/autoload.php`
и самого `legacy.php` при выборе движка). К оригиналу — те же три обращения.

**Чего нет ни в одном режиме:** `file_get_contents` оригинала, `md5_file`, `getimagesize`, декодирования GD,
`filesize` оригинала. Последнее убрано в этом проходе: метрики для лога собираются только если их кто-то
запишет (`LoggerInterface::logsRequests()`), а `ETag` больше не требует `stat` кеш-файла — он выводится из ключа:

```php
$etag = '"' . md5($key . '.' . $target->cacheExtension()) . '"';
```

Ключ уже содержит `mtime`, размеры, кроп, режим и отпечаток настроек, поэтому ETag меняется ровно тогда,
когда меняется содержимое варианта. Стоимость — один `md5` от короткой строки (десятки байт), не от файла.

**Динамика:** было 14 обращений на hit → стало **10** (−29 %), при этом чтения оригинала не было и раньше —
политика соблюдалась, но лишние `stat` устранены.

**Стоимость маршрутов (`aliases.json`, §17).** Тот же запрос, тот же инструмент:

| Ситуация | Основной движок | `legacy.php` | Что добавилось |
| :--- | :---: | :---: | :--- |
| файла маршрутов нет | 11 | 13 | `is_file` по `aliases.json` |
| файл есть, путь обычный | 12 | 14 | + чтение небольшого JSON |
| путь маршрутизирован (пресет/псевдоним) | 13 | 15 | + `is_file` проверки «реальный файл важнее» |

Чтения **оригинала** нет ни в одном из этих случаев: добавляются только обращения к маленькому JSON
и одна проверка существования буквального пути. Файл в корне сайта (`photo.jpg`, без слэша) не разбирается
вовсе — маршрутов там быть не может, поэтому лишней работы нет.

**Относительная скорость** (WASM, файловая система в памяти — абсолютные миллисекунды не переносятся на реальное железо,
важно отношение): hit 0.04–0.10 мс, генерация 25.7–37.0 мс, то есть **hit быстрее генерации в 290–925 раз**.

**Проверено:** `ApplicationTest::testCacheHitDoesNotTouchHugeOriginal` (оригинал на 140 Мп отдаётся из кеша,
рендер вызван ровно один раз — на прогреве), `testCacheHitSurvivesCorruptedOriginal` (оригинал побитово испорчен,
но вариант в кеше есть → `200 hit`), `testDisabledLoggerCollectsNothing`, интеграция №1, №2.

**Вердикт: выполняется.**

## 6. Слабые серверы

Что сделано специально для дешёвого хостинга:

1. **Боевой режим — редирект на статику.** PHP делает 10 обращений к ФС и завершается; тело отдаёт веб-сервер, воркер свободен.
2. **Никакого прогрева.** Кеш создаётся по первому URL, вариант существует ровно для тех размеров, которые реально запросили.
3. **Лимиты входа до декодирования** (`max_input_megapixels`, `max_input_bytes`) — GD не пытается аллоцировать 140 Мп.
4. **Атомарная запись + `flock`** — параллельные запросы не генерируют один вариант дважды и не видят недописанный файл.
5. **Лог по умолчанию молчит** и не собирает метрики (`log_level=error`).
6. **Движок без зависимостей** — на PHP 7 не нужно ни Composer, ни память под автозагрузчик Intervention.

**Вердикт: выполняется.**

## 7. Совместимость URL API

Ни один параметр не переименован и не удалён: `w`, `h`, `m`, `g`, `fm`, `ct`/`cr`/`cb`/`cl`, `name`,
путь вида `/iar/path/to/photo.jpg?w=800`. Прежние ссылки работают без изменений.

**Проверено:** 50 интеграционных сценариев гоняют реальные HTTP-запросы через точку входа (встроенный сервер PHP

`If-None-Match`, `Accept`.

## 8. Браузерный кеш: всегда актуальная версия

| Ситуация | Заголовки | Почему браузер не покажет старое |
| :--- | :--- | :--- |
| Обычный режим | `Cache-Control: no-cache` + `ETag` из ключа | браузер обязан перепроверить; при совпадении — `304` без тела |
| Оригинал изменился | новый `mtime` → новый ключ → новый ETag и новый URL кеша | `304` невозможен, приходит `200` с новым телом |
| Редирект на кеш | сам редирект — `no-cache`; файл кеша — `public, max-age=31536000, immutable` | URL файла версионирован именем, при смене оригинала меняется URL |
| `static_mode=true` | `301` + `immutable` | режим для заведомо неизменяемых ресурсов |
| `disable_cache=true` | `no-cache, no-store, must-revalidate`, ETag нет | режим разработки |
| Аварийная отдача оригинала | `no-store` | сбойный ответ не залипает в браузере |
| Формат зависит от `Accept` | `Vary: Accept` (для GIF/SVG — нет) | CDN не отдаст WebP тому, кто его не понимает |

`.htaccess` ставит `immutable` только файлам внутри `/cache/` (`SetEnvIfNoCase … IAR_CACHE_FILE`), сам обработчик остаётся `no-cache`.

**Проверено:** `ApplicationTest::testEtagIsDerivedFromCacheKey`, `testDifferentSizesHaveDifferentEtags`,
`LegacyTest::testEtagIsStableAndChangesWithOriginal`, `testNotModifiedOnMatchingEtag`, `testStaticMode*`,
интеграция №2 (304), №5/№6 (301 и immutable), №7 (no-store), №14 (Vary).

**Вердикт: выполняется.**

## 9. Надёжность: всегда вернуть файл

Три уровня защиты, одинаковых в обоих движках:

| Уровень | Что происходит | Ответ |
| :--- | :--- | :--- |
| 1. Сбой обработки (`ProcessingException`) | вариант не создан | `302` на оригинал, `no-store`, `X-Iar-Fallback: original`, причина в лог |
| 2. Сбой сборки/конфига (`Throwable`, в т.ч. `Error` на PHP 7) | приложение не собралось | `200` с телом оригинала, `no-store`, `X-Iar-Fallback: original` |
| 3. Фатальная ошибка (`E_ERROR`, нехватка памяти) | `try/catch` не срабатывает | shutdown-обработчик отдаёт оригинал; если нельзя — нейтральный `500` без путей |

Клиентские ошибки (`400/403/404/405/413`) **не** приводят к отдаче оригинала: иначе белый список расширений
можно было бы обойти, запросив `secret.txt` и спровоцировав сбой. Аварийный путь повторно проверяет
расширение и нахождение файла внутри корня сайта.

Дополнительно: пустой результат рендера никогда не публикуется в кеш (`Renderer produced an empty image.` → оригинал),
а сбой конфигурации всё равно попадает в лог — `Bootstrap::emergencyLogger()` читает настройки лога из сырого
массива конфига, даже если сам конфиг невалиден (найденный и исправленный в этом проходе дефект).

**Проверено:** `BootstrapTest` — 39 тестов, среди них `testFatalErrorServesTheOriginal`, `testFatalErrorWithoutOriginalIsNeutral500`,
`testFatalFallbackRespectsHead`, `testOriginalFileRejectsNonImage/Traversal/NullByte/MissingAndDirectory/BadDocumentRoot`,
`testEmergencyLoggerMergesLocalConfig`; `LegacyTest::testShutdownServesOriginalOnFatalError`, `testRunFallsBackOnPhpError`,
`testFallbackRejectsNonImage`; интеграция №47 (битый оригинал), №48 (неполная установка), №49 (нет `vendor/`).

**Вердикт: выполняется.**

| Анимированный GIF, ресайз в GIF | кадры сохраняются (декодер анимации + покадровый энкодер) | оригинал (`302`) |

Определение анимации дешёвое: у GIF — количество кадров (`Image::count()`), у WebP — наличие чанка `ANMF`

**Проверено:** `ResizeServiceTest::testAnimatedGifKeepsFrames` (число кадров до и после совпадает),

**Вердикт: выполняется** — изображение не исчезает и не теряет кадры; различие движков задокументировано в README.

## 11. PHP 7+: конфликт найден и закрыт

**Проблема, выявленная аудитом.** Требование «гарантированно PHP 7+» конфликтовало с реализацией:
`intervention/image` 3.11.7 и `intervention/gif` 4.2.4 объявляют `"php": "^8.1"`, а код `src/` использует
enums, `readonly`, `match`, `str_contains`. На PHP 7 такой продукт не запускался вовсе.

**Решение — два движка с общим контрактом.** Добавлен `legacy.php`: один файл, синтаксис PHP 7.0,
только GD, ноль внешних зависимостей. `index.php` выбирает движок автоматически:

```php
if (PHP_VERSION_ID < 80100 || !is_file($iarAutoload)) {
    require_once …'/legacy.php';   // PHP 7.0–8.0 или нет Composer
    iar_legacy_run($_GET, $_SERVER, …);
    return;
}
// иначе — полный движок src/ (Intervention, AVIF, Imagick)
```

Общий контракт обоих движков: URL API, имена кеш-файлов (значит и сам кеш), заголовки, ETag/304,
политика редиректа, формат лога, поведение при сбоях. Совпадение ключей проверяется тестами напрямую,
а не декларацией.

**Кросс-версионный прогон** `php tests/legacy-compat.php` (57–59 проверок политик в каждом прогонe):

| PHP | Проверок | Провалов |
| :--- | :---: | :---: |
| 7.0.33 | 57 | 0 |
| 7.1.30 | 57 | 0 |
| 7.2.34 | 57 | 0 |
| 7.3.33 | 57 | 0 |
| 7.4.31 | 59 | 0 |
| 8.0.30 | 59 | 0 |
| 8.1.23 | 59 | 0 |
| 8.2.10 | 59 | 0 |
| 8.3.0 | 59 | 0 |
| 8.4.0 | 59 | 0 |

На PHP 7.0–7.3 проверок на две меньше: GD в этих сборках не умеет WebP, соответствующие проверки пропускаются
самим тестом (движок в этом случае просто не выбирает WebP).

CI получил отдельный джоб `legacy` с матрицей 7.0 → 8.4: линковка `index.php`, `legacy.php`, `tools/cache.php`,
`tests/legacy-compat.php` на каждой версии плюс прогон проверок и вызов CLI кеша.

**Вердикт: выполняется.** Оговорка, которую важно знать: на PHP 7 доступен только движок без зависимостей
(ограничения по анимации и SVG описаны в разделе 10 и в README). Полный движок требует PHP ≥ 8.1 — это
ограничение самой библиотеки, а не кода IAR.

## 13. Отладочный лог

Требования: только для отладки, выключен по умолчанию, без ротации, но при включении на уровне ошибок —
достаточно подробный для разбора.

`log_level`:

| Уровень | Что пишется | Стоимость на cache hit |
| :--- | :--- | :--- |
| `error` (по умолчанию при `logging=true`) | только `fail`: `reason`, `status`, `url`, `redirect`/`fallback`, `stage`, `duration_ms` | **0** дополнительных обращений к диску |
| `info` | плюс `hit`/`miss` со статусом, весом до/после, экономией, длительностью | 2 `filesize` |
| `debug` | плюс параметры запроса | 2 `filesize` |

Формат — одна JSON-строка на событие, файл на день, без ротации. Чувствительные ключи
(`token`, `pass`, `secret`, `auth`, `api_key`, `session`) редактируются, переводы строк экранируются
(защита от подделки строк лога). Формат одинаков у обоих движков.

**Проверено:** `LoggerTest` (14), `LegacyTest::testLoggingDisabledByDefault`, `testErrorLevelIsSilentOnSuccess`,
`testInfoLevelLogsHitAndMiss`, `testDebugLevelIncludesParams`, `testErrorLevelLogsFailuresWithReason`,
`testLogRedactsSensitiveKeysAndNewlines`, `testLogSkipsInvalidUtf8`; интеграция №44–47.

**Вердикт: выполняется.**

| Изменение | Файлы | Причина |
| :--- | :--- | :--- |

## 15. Ограничения и честные оговорки

1. **Абсолютные миллисекунды не измерялись на реальном железе.** Прогоны выполнялись в PHP, собранном в WebAssembly
   (нативного PHP и Composer в окружении нет). Достоверны счётчики обращений к ФС, число декодирований и байты;
   временные отношения (hit быстрее генерации в 290–925 раз) приведены с оговоркой, что файловая система в памяти.
2. **AVIF и Imagick не проверялись вживую** — сборки GD без AVIF, расширение Imagick отсутствует. Ветки помечены
   `@codeCoverageIgnore` и вынесены в отдельный CI-джоб `imagick` с `IAR_STRICT_COVERAGE=1`.
3. **23 исполнимые строки исключены из измерения маркером `@codeCoverageIgnore`** (при `IAR_STRICT_COVERAGE=1`
   измеряются и они): 22 в `legacy.php` — 10 строк растеризации SVG через Imagick, 3 строки AVIF,
   9 строк отказов `tempnam`/записи/`scandir`/`flock`; 1 в `src/Domain/ResizeService.php` — AVIF-энкодер.
   Отказы файловой системы не воспроизводятся переносимо; те же ветки основного движка проверяются
   инъекцией (`tests/Support/FaultyCacheStore.php`), а Imagick/AVIF — отдельным CI-джобом.
   Все остальные **1449 исполнимых строк покрыты на 100 %**.
4. **PHPStan, PHP-CS-Fixer и Infection не запускались** — нет Composer и доступа к packagist. Конфиги и CI-джобы
   на месте; их прогон остаётся за CI.
5. **Анимированный GIF на PHP 7 отдаётся оригиналом.** Покадровый ресайз без библиотек потребовал бы
   собственного GIF-кодека — это противоречит политике минимума зависимостей и надёжности.

## 17. Маршруты в пути: псевдонимы, пресеты, макросы

**Формулировка пользователя:** JSON-настройка рядом с сайтом, где сегмент URL — псевдоним
реального каталога (`iar/z/file.png` → `/z/s/d/f/file.png`), а последняя папка — набор
GET-параметров (`/1000/`) или маска одного размера (`x-1000` — ширина, `y-1000` — высота).
Файл-пример должен лежать в репозитории и работать по принципу «положил и работает».

**Реализация:** `aliases.json` (пример в комплекте), `src/Http/PathRouter.php`,
`src/Http/Route.php`, тот же разбор в `legacy.php` (`iar_legacy_router`, `iar_legacy_route`,
`iar_legacy_folder_params`, `iar_legacy_merge_params`). Ключ конфига — `aliases_file`.

| Политика | Как соблюдена | Доказательство |
| :--- | :--- | :--- |
| «Положил папку и забыл» | файл лежит рядом с `index.php`, читается сам, регистрация не нужна | `BootstrapTest::testAliasAndServeResizedImage`, сценарий 50 |
| Старые ссылки не ломаются | реальный файл на диске важнее виртуального маршрута | `PathRouterTest::testRealFileWinsOver*`, сценарий 55 |
| Совместимость URL API | пресет = те же параметры, кеш-ключ совпадает с query | сценарий 51, `LegacyTest::testLegacyPresetCacheKeyMatchesPlainQuery` |
| Явный запрос главнее | `?w=` перекрывает пресет, пустое значение считается отсутствующим | `RequestTest::testExplicitQueryWinsOverPathParameters`, сценарий 53 |
| Один макрос — один параметр | `x-` только ширина, `y-` только высота, 1…6 цифр, ≥ 1 | `PathRouterTest::testMacroSetsExactlyOne*`, сценарий 52 |
| Только последняя папка | вложенные папки не интерпретируются | `PathRouterTest::testOnlyLastFolderIsInterpreted`, сценарий 54 |
| Всегда вернуть файл | за псевдонимом оригинал отдаётся телом (`200`), а не редиректом на реальный путь | `ApplicationTest::testAliasedFailureServesOriginalInline`, сценарий 56 |
| Псевдоним не раскрывает путь | нет `Location` с реальным каталогом; `aliases.json` закрыт в `.htaccess` и в примере nginx | сценарий 56, `.htaccess` |
| Сломанный JSON не ломает картинки | маршруты выключаются, причина в логе (`stage: aliases`) | `BootstrapTest::testBrokenAliasesJson*`, сценарий 58 |
| Аварийный путь тоже понимает маршруты | `Bootstrap::emergencyRouter()`, `iar_legacy_fallback()` | `BootstrapTest::testEmergencyFallbackServesAliasedOriginal` |
| Нет выхода за корень оригиналов | `..`, `.`, NUL, схемы, буквы дисков отбрасываются при загрузке | `PathRouterTest::testUnsafe*`, `LegacyTest::testLegacyRejectsSchemes*` |
| Гарантия PHP 7+ | тот же разбор на синтаксисе PHP 7.0, паритет с основным движком | `LegacyTest::testLegacyRouterMatchesMainEngine`, `tests/legacy-compat.php` (83–85 проверок) |
| Cache hit остаётся мгновенным | +1…3 обращения к ФС, чтения оригинала нет | §5, таблица стоимости маршрутов |
| Оба движка делят кеш | ключ строится из итоговых пути и параметров | сценарий 61 |

**Что изменилось в коде:**

| Изменение | Файлы |
| :--- | :--- |
| Разбор маршрутов, значение маршрута | `src/Http/PathRouter.php`, `src/Http/Route.php` |
| Приоритет query над путём, итоговые параметры в логе | `src/Http/Request.php` (`params`, `route`) |
| Отдача оригинала за псевдонимом вместо `302` | `src/Application.php`, `src/Http/OriginalResponse.php` |
| Маршруты в аварийном пути, сырой конфиг как источник `aliases_file` | `src/Bootstrap.php` (`rawConfig`, `emergencyRouter`) |

пресет не может менять имя файла или настройки движка; макрос задаёт одно измерение;
виртуальной может быть только последняя папка. Маршрутизация добавляет 1–3 обращения
к ФС на запрос (см. §5) — это плата за короткий URL, содержимое оригинала не читается.
